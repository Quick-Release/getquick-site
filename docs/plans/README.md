# Plans

Migration and multi-step implementation plans worth keeping around after
they're executed — for context on why something changed the way it did, not
just what changed. One kebab-case Markdown file per plan.

Day-to-day task planning belongs in GitHub Issues, not here; only plans with
lasting reference value (a migration, a phased rollout) belong in this
directory.
